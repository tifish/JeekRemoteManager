# 存储、设置与导入

涉及 `Services/ConnectionStore.cs`、`SettingsService.cs`、`RemoteScriptStore.cs`、`Models/AppSettings.cs`、三个导入器，以及 JeekTools 的 `SettingsStorage.cs`、`JsonSettingsFile.cs`。

## 连接树

一个连接一个文件，用文件夹树组织，根在活动存储位置的 `Config\Connections` 下。选这个形态而不是单一数据库，是为了让连接可以被单独拷贝、同步、版本控制。

因此有几条约束：

- **文件名是权威的。** `Load` 之后会把内存里的 `Name` 与文件名对齐。
- `Name` 经 `SanitizeName` 过滤掉 Windows 非法字符。这个过滤在每次重命名、保存、复制、文件夹操作里都会跑，所以非法字符集合被提升成查找表而不是逐次扫描 41 元素数组；大多数名字本来就是干净的，此时不构造新字符串。
- 重命名撞上已有的**不同**文件时自动加后缀消歧。
- **`ConnectionId` 是稳定身份**，用于关联机器本地的状态（如 AI 会话历史）。重命名和移动保留它，**复制会生成新的**。老文件在首次加载时补写一个 id。
- `ReadTree()` 一次性读完整棵树，且**设计成可以在工作线程上调用**。原先逐个文件内联加载意味着每次重建都在 UI 线程上读取并反序列化每个连接——目录放在网络盘或同步盘上时非常明显。
- **同步重建靠缓存变便宜，而不是改成异步。** 重命名、移动、粘贴、保存之后要立刻选中新节点，所以这些用户动作仍在 UI 线程上同步 `ReloadTree`。代价在于原先每次都要重读、重新解析全部连接文件。现在 `ConnectionStore` 按"路径 + 大小 + 修改时间"缓存每个文件的**文本**：目录枚举本身就带回大小和时间，没变的文件不再打开，只读变了的那几个。缓存的是文本而不是解析后的对象——编辑器会就地修改 `Connection`，每次读取都必须发出新实例。回归检查是 Debug MCP 的 `connection_tree_read_cache_check`。
- 不可读/格式错误的文件被跳过，不中断整棵树。
- **删除进回收站。** `DeleteFile`/`DeleteFolder` 经 `RecycleBin`（`SHFileOperation` + `FOF_ALLOWUNDO`，不带任何 shell UI）移入回收站，手工删除和 MCP 删除走同一条路。可恢复是 MCP 删除不需要确认的前提；不支持回收站的位置（部分网络盘）上 Windows 会直接删除。
- **区分"自己的写"和"外部改动"靠已读取的指纹，不靠时间窗。** `KnownSignature` 是"树当前反映的磁盘状态"的指纹（根下每个文件的相对路径 + 大小 + 修改时间、每个文件夹的相对路径，只读元数据）。`ReadTree` 前后各算一次，一致且期间没有自身写入才采用；`OwnWrite` 在写入开始和结束时使指纹失效，不能认领整个写后目录，因为外部修改也可能落在写入期间。只有真正读取了树才能再次确认同步。监视器的防抖到期时在后台比较实时指纹；用户动作或 MCP 已显式重建树时，监听器仍跳过重复重载。
  - 原先的做法是"自己写盘后 1 秒内的事件全部丢弃"。连接目录在 Syncthing 同步盘上，落在这 1 秒里的外部改动会被一起丢掉，树一直停在旧状态。回归检查是 Debug MCP 的 `connection_external_change_check`。
  - 批量写（改主密码后的重新加密）用 `RunBatch` 包起来，写入期间不扫描指纹，结束后由下一次树读取确认磁盘状态。`connection_external_change_check` 也检查批量写入中途的外部文件最终出现在树中。
  - 便携模式下漫游设置文件同理按**内容**判断（`RoamingFileMatchesLastSave`），不按时间。

## 设置：按漫游行为分层

`SettingsService` 建在 JeekTools 的 `SettingsStorage`（路径方案）和 `JsonSettingsFile`（合并/写入）之上。

- **机器本地设置**永远在 `%LOCALAPPDATA%\JeekRemoteManager\Config`：面板布局尺寸、编辑器路径、AI 运行模式这些跟机器绑的东西。
- **漫游偏好**在活动存储位置的 `Config` 文件夹里，和连接、脚本数据放在一起。

存储位置有三种：AppData（默认）、便携（可执行文件旁的 `Config` 文件夹）、自定义目录。**可执行文件旁存在 `Config` 文件夹时强制便携模式**，不管保存的设置说什么——这样把整个目录拷到 U 盘就能用。

### 三方合并

多个实例可能同时在跑，`JsonSettingsFile` 用跨进程锁写入并做三方合并：只有 baseline 与 local 之间有差异的属性才覆盖盘上的值。这样两个实例各改各的设置不会互相抹掉。

**baseline 必须克隆。** `Settings` 会从合并结果重建，未克隆的 baseline 会与它共享 `List`/`Dictionary` 实例；下一次保存就会拿这些集合和它们自己比较，看不出变化，于是静默丢掉用户的修改。这个坑在代码里出现了三次，都加了注释。

### 一次性迁移

有些键从漫游文件搬到了机器本地文件。启动时做一次单向采纳：机器文件尚未定义的已迁移键，从漫游文件里取过来，用户的现有值不丢。迁移后 baseline 停在迁移前的盘上状态，让紧接着的保存把采纳到的值通过合并写出去。

## 远程脚本存储

脚本套件是目录：一个 `params.conf` 声明参数（名字、类型、默认值、枚举选项），若干 `.sh` 脚本文件。有两个根：应用内置的和用户的。

`SaveSuite` 的合并语义是刻意的：**参数在提供时整体替换套件定义，脚本按文件名合并**——调用方（尤其是 MCP 工具）可以只更新一个文件而不用把整套重发一遍。

## 导入器

三个导入器（FinalShell、SecureCRT、Xshell）共享同一个形状：递归遍历源目录，保留相对文件夹布局，同名文件夹合并进已有文件夹，重名连接由 `ConnectionStore.Save` 自动加后缀。

各自的存储格式差异和密码处理见 [凭据保护](secrets.md)。

## 存储位置迁移

`MoveConfigRoot` / `MoveTreeContents` 支持在三种存储位置之间搬家。两条保护：

- **拒绝把一棵树拷贝/移动进它自己或它的子树**（会无限递归）。
- 优先尝试同卷目录重命名（快）；跨卷时 `Directory.Move` 会失败，回退到递归复制 + 删除。

迁移时连接文件里的 `ConnectionId` 会被一起带过去（而普通的"复制连接"会换新 id）。
