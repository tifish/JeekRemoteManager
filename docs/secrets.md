# 凭据保护

涉及 `Services/MasterKeyService.cs`、`PasswordProtector.cs`、`App.axaml.cs` 的解锁流程。

## 设计目标

1. 用户日常不用输密码，但密码也不能明文躺在磁盘上。
2. **单个连接 `.json` 文件可以拷到另一台机器**，在那边输入主密码就能用。
3. 任何对外接口（MCP、日志、诊断）都不返回密码。

第 2 条决定了不能用 DPAPI 保护连接密码——DPAPI blob 绑定机器/账户，换台机器就废了。

## jrm1 信封

每个保存的密码是一个自包含的 blob：

```
jrm1:Base64(salt || nonce || cipher || tag)
```

AES-256-GCM（salt 16 字节、nonce 12 字节、tag 16 字节），密钥从主密码 + blob 自带的随机 salt 用 PBKDF2 派生，210,000 次迭代。**salt 存在 blob 内部**，这就是可移植性的来源：同一个 blob 在任何机器上都能用同一个主密码解开。

## 主密码与 DPAPI 缓存

主密码材料本身缓存在 `%LOCALAPPDATA%` 下，用 DPAPI（当前用户）保护，附加一段绑定应用/缓存版本的额外熵。这份缓存是纯本地的加速器：

- 它**只**用于跳过启动时的密码提问。
- 它永远不跟着便携数据走。
- 删掉它（`ClearCache`）只意味着下次启动要输密码。

## 启动解锁流程

`App.UnlockThenStartAsync` 的顺序是：

1. 试 DPAPI 缓存静默解锁。
2. **解出来的密钥还必须能真正解开至少一个已存在的 `jrm1` blob**。解不开就锁上、清缓存、当作没解锁。这一步防的是"缓存和实际数据不匹配"——比如用户在别处换了主密码后把连接目录同步过来。
3. 仍未解锁则弹对话框。对话框只有一种模式（密码 + 确认），标题按"连接文件是否已存在"在"设置"和"解锁"之间切换措辞。
4. 输入的密码同样要能解开至少一个已存在的 blob 才被接受。
5. 用户取消 → 退出进程。**没有"跳过加密直接用"这条路。**

校验函数 `CanReadStoredPasswords` 在**第一个成功**处停下，所以常见情况只付一次密钥派生的代价；一个 blob 都没有（全新安装）时直接算通过。

`EnumerateStoredPasswordBlobs` 刻意不走 `Load`：`Load` 还会解析堡垒机模板并给缺 id 的文件回写 id，而几秒后连接树就要把每个文件读一遍，这是白做的工作。文本里没有 blob 的文件根本不解析。

## 并发：为什么密钥材料从不离开锁

`_secretGate` 同时保护主密钥材料和派生密钥缓存。原因：主密码变更时两者都会**就地清零**，而这个操作来自 UI 线程；与此同时连接对象正在后台线程上被构建。在锁外读取任何一方，都可能在一个正被清零的数组上派生或解密——表现为一条本该成功的连接静默地报"密码错误"。

所以规则是：**密钥材料永远不在锁外被触碰，派生出的密钥也永远不交出去**。派生在锁内做，解密也在锁内做。代价是冷调用方要等，但这正是"就地清零安全"的前提；而且两个同时想解同一个 blob 的调用方现在共享一次派生，而不是各派生一次。

## 派生密钥缓存

按 blob 自身的 salt 做键。因为每个 blob 有固定的随机 salt，同一个 blob 总是派生出同一个密钥——而在树里点一下连接就会重新解密它的密码和私钥口令，没有缓存的话每次点击都是一次 210k 迭代的派生。

缓存有容量上限，防止长会话无限增长（实际上每个存储的密文一条，远低于上限）。**加密时的新 salt 不进缓存**：全新的 salt 意味着这条缓存永远不会被复用，只会把真正能复用的解密密钥挤出去。

## 唯一的例外：RDP

`PasswordProtector.EncryptForRdpFile` 仍然走 DPAPI，因为它必须产出 `mstsc.exe` 期望的那个确切的、机器本地的格式：明文密码编码成 UTF-16LE，DPAPI（当前用户）加密，再渲染成大写十六进制串，写进 `.rdp` 的 `password 51:b:` 字段。这里没有可移植性的诉求——`.rdp` 文件本来就是临时生成、用完即删的。

## 对外暴露的规则

- MCP 产品面的响应**按显式字段白名单逐个组装**，从不序列化 `Connection` 模型。这样以后往模型上加字段不会意外泄漏。
- 只回答 `hasPassword` 这类布尔值。
- 需要用户输入的秘密（主密码、二次因子）只在 GUI 里输入，**永远不作为工具参数**。
- 连接编辑器里的"显示明文密码"需要重新输入主密码，且短暂空闲后自动关闭。这个状态挂在主 ViewModel 上而不是编辑器上，是为了在连接之间切换时不把它重置掉。

## 导入器里的密码

三个导入器（FinalShell / SecureCRT / Xshell）对密码的处理各不相同，共同点是**能力所限时宁可不导入**：

- **FinalShell**：密码用机器绑定密钥加密，需要 FinalShell 自己的运行时才能解，所以**完全不导入密码**，用户在编辑器里重输。
- **SecureCRT**：Password V2（`02:hex`，AES-256-CBC，key = SHA256("")）在配置口令为空时可以尽力解；`03:hex`（bcrypt-pbkdf2）没有口令 UI 就不支持。
- **Xshell**：RC4 加密，密钥随版本而变（SID / 用户名+SID / 主密码）。只对当前 Windows 用户、无主密码的情况尽力解。
