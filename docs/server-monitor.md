# 服务器监控面板

涉及 `Services/ServerMonitorSession.cs`、`ViewModels/ServerMonitorViewModel.cs`。

## 采样通道：一条隐藏的复制 shell

监控不为每次采样开新的 exec 通道，而是在终端**共享的 SSH 传输**上开一条**持久的隐藏 shell**，并让它跟着"复制会话"的登录命令序列走（即从 `#duplicate` 段开始）。

这么做的理由：堡垒机场景下，一条新开的 shell 落在菜单上而不是目标机器里。走复制会话的登录序列，监控 shell 才能到达和"复制标签页"同一个目标。`ChannelMode` 属性把这件事暴露给 Debug MCP 验证——它必须是 `PersistentDuplicatedShell`。

登录过程中输出会喂给 `LoginMenuOutputCapture`，所以 `#select` 能匹配当前屏幕上的菜单；并且在打第一条选择之前要**先等提示符/菜单出现**。

## 解析策略：优先 /proc

尽量读 `/proc` 而不是解析工具输出，这样解析对 locale 和 busybox 都免疫：

| 数据 | 来源 |
| --- | --- |
| CPU | `/proc/stat` 聚合 cpu 行（字段 4 = idle，字段 5 = iowait，都算不忙） |
| 内存/交换 | `/proc/meminfo`，优先用内核自己的 `MemAvailable`；老内核回退到 free + buffers + cached |
| 网络 | `/proc/net/dev` 的累计计数（接收字节是字段 0，发送是字段 8），跳过 loopback |
| 主接口 | `ip -o route show to default` 里 `dev` 后面的名字；否则取最忙的非 loopback 接口 |
| 进程 | `ps -eo rss,pcpu,comm`；busybox `ps` 作为降级回退（只有命令名，没有大小） |
| 磁盘 | `df -P -k`，只保留真实块设备（文件系统以 `/` 开头），按挂载点去重 |

**每个区块都用哨兵行标记**，这样某个工具缺失只影响它自己那一块。一次采样没收集到的区块（重的区块只在第 N 个 tick 收集）或解析失败的区块在快照里是 `null`——面板继续显示上一个值或一个短横线，**永远不会整块报错**。

PTY 承载的堡垒机 shell 可能往本该纯文本的命令输出里注入颜色或控制序列，所以**解析任何字段之前必须剥掉 ANSI**。

## 轻重 tick

轻区块（CPU、内存、网络这些变化快的计数器）每个 tick 采；重区块（进程列表、挂载点、地址）每 N 个 tick 采一次。**只有轻 tick 参与延迟估算**，这样 ps/df 的开销不会污染延迟数字。

进程快照保留完整列表而不是只留内存前八——面板按用户选的内存/CPU 排序自己挑行，不能因为某个进程不在内存前八就把 CPU 大户丢掉。

## 挂起语义

面板不在屏幕上时停止采样（包括窗口最小化或隐藏到托盘）。用户看不见的服务器每两秒发一条远程命令是纯浪费。

但**挂起只停止采样，不关闭 shell 和它的登录序列**。每次切标签页都重跑一遍堡垒机登录，代价远大于省下的那几次采样；这里的目的是"别再和服务器说话"，不是"放弃通道"。

切换标签页还有一个**宽限期**：来回翻标签或短暂最小化不应该停掉再重启轮询循环，所以挂起要等过宽限期；切回来则立即取消倒计时。

采样中断恢复后，累计的 CPU 和网络计数器之间的空档会让差值失去意义，所以**重新开始计算差值**，避免恢复后第一个采样是一个假尖峰。

## 失败处理

反复采样失败后会话进入失败态并通知面板，但**继续以慢间隔探测**，下一次成功就自动恢复。
