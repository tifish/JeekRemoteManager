# 应用外壳（窗口、标签页、托盘、本地化）

涉及 `Views/MainWindow.axaml.cs`、`ViewModels/MainWindowViewModel.cs`、`TreeNodeViewModel.cs`、`Models/ApplicationMenuDefinition.cs`、`Views/PasswordImeGuard.cs`、`App.axaml.cs`。

## 单实例与托盘

第二次启动时只做一件事：唤醒已有实例然后退出。唤醒走一个具名事件；老版本/竞态实例可能还没建好事件，此时回退到"找可见窗口并前置"的老办法。

`ShutdownMode = OnExplicitShutdown`：**关主窗口只是隐藏到托盘**，退出走托盘菜单的 Exit。

隐藏到托盘只拦截 `WindowCloseReason.WindowClosing`。`OSShutdown`（关机/注销）及 `ApplicationShutdown` 必须放行，不能因 `_exitRequested` 尚未设置而取消；窗口已隐藏时规则也相同。不以 `IsProgrammatic` 区分：程序调用 `Window.Close()` 仍是普通关闭，而系统退出必须依据关闭原因判断。`window_close_reason_check` 对隔离窗口走真实关闭管线，覆盖三种原因、可见/隐藏以及程序/非程序调用，不触发实际系统关机或应用退出。

`Closing` 是可取消的关闭请求，不是销毁通知。主窗口自己的处理器先执行，随后 `App.OnMainWindowClosing` 才取消关闭并隐藏窗口，所以即使在前者里检查 `e.Cancel` 也不可靠。堡垒机会话池和全局 agent 的释放必须放在 **`Closed`**；否则点过一次关闭按钮就会永久销毁仍在使用的池，现有终端继续工作但新连接都无法复用，重复要求二次验证。设置仍可在 `Closing` 时保存。`bastion_tray_lifecycle_check` 用隔离窗口和真实托盘处理器验证隐藏、恢复、再次入池，以及真正关闭后的释放。

设置状态在三个时机落盘：正常退出、应用失活、以及**未处理异常导致进程即将死亡时**（尽力而为的最后一次保存，且这里的失败绝不能掩盖原始错误）。

## 共享的应用菜单

`ApplicationMenuDefinition.Items` 是一份**有序的动作清单，主窗口的溢出菜单和托盘菜单都迭代它**，所以顺序、标签、动作永远一致。平台特有的项（托盘的"显示"）留在清单外面。

托盘调用的命令会打开以主窗口为 owner 的对话框，**`ShowDialog` 在隐藏的 owner 上会挂死**，所以除了 Exit 之外都要先把窗口浮出来。语言变更时重建托盘菜单，让本地化标签保持最新。

## 连接树

`TreeNodeViewModel` 既表示文件夹也表示连接，`FullPath` 是它映射的文件系统路径。

**"最近"是合成分组**：它下面的连接节点是快捷方式，选中会重定向到真实的树节点；分组本身上的结构性操作被禁掉。

多选相关的两个规则：

- 批量命令作用的节点是"多选（且仍包含锚点）时用多选，否则用单选节点"。
- **结构性批量操作（删除、复制、移动）要先剔除位于另一个已选文件夹内部的节点**，否则同一项会被处理两次。

树的加载在工作线程上完成（见 [存储](storage.md) 的 `ReadTree`）。

### WSL 发行版选择

连接编辑器的 WSL `ComboBox` 用 `AvailableWslDistros` 作 `ItemsSource`，并双向绑定 `WslDistro`。列表内容不变时必须保留同一个数组实例：替换等值数组也会清空选择、回写 null，再由保留旧值的逻辑触发列表通知，形成同步递归并使新建连接栈溢出。每次仍重新检查发行版名称及未安装的当前值，仅在内容或顺序变化时替换缓存。`wsl_editor_selection_check` 用隔离编辑器及正式模板的编译绑定覆盖瞬时空值与编辑器切换，不写入用户连接。

## 标签页

- 固定的第一个标签是编辑器标签（批量脚本面板打开时会接管它，标题从"编辑"变成"批量运行"）。全局 agent 标签也是常驻标签。这两个**永远不会被"关闭其它标签"关掉**。
- **会话编号复用**：同一连接上的第一个标签是 1（不显示后缀），复制出来的是 (2)、(3)……取的是当前空闲的**最小**编号，所以关掉 (2) 再复制会重新用 (2)，而不是无限增长。这个编号同时决定 AI 工作区的目录名。
- **复制标签页优先搭已有传输的便车**（在已认证连接上开新通道，瞬时完成、无需重新登录）；源标签的传输不可用时才新拨一条。

### 多行标签分页与搜索

`RightTabs` 的 `PagedTabPanel` 按标签实际宽度换行，再按行分页。每页最多行数默认 **5**，标签栏旁的“行数”可即时调整为 1–20，保存在机器本地的 `TerminalTabMaxRows`。窗口变窄时重新计算分页；窗口高度不足时进一步减少每页行数，给内容区预留至少 120 DIP（一个标签行本身不可再分割）。页码使用“当前页 / 总页数”，上一页、下一页到边界时禁用；无匹配项时显示 `1 / 1` 和匹配数量 0。

分页和搜索只改变**标签头的布局**，不从 `TabControl.Items` 移除会话、不隐藏整个 `TabItem`，也不切换当前终端。手动翻页可以暂时浏览其它标签；新开或显式切换会话时自动定位选中标签，窗口调整和行数变化继续保持这个标签（手动翻页后则保持所浏览页的第一个标签）。关闭标签时重新计算页数并收敛到有效页。

标签头总共不超过一行且没有正在输入的搜索时，整条操作栏自动隐藏；新增、关闭标签或调整窗口宽度使标签变为多行时自动显示。行数按所有分页合计，因此即使每页上限设为 1，仍保留翻页操作。搜索期间即使结果只有一行或没有结果也保留操作栏，确保可以修改和清除搜索。

搜索不区分大小写，按空格分词并同时匹配显示名、完整连接名、主机、连接路径及会话编号；结果继续按原标签顺序分页。Enter 激活当前结果页的第一个标签，Escape 或清除按钮退出搜索并定位当前标签。外部切换到不匹配搜索的会话时清除过滤，确保当前标签可见。标题原有的尾部保留、相邻差异高亮和完整名称 tooltip 均保留；拖拽插入只参考当前页的标签，并同时考虑行和列。

纯分页边界与设置持久化由 `TabPaginationTests` 覆盖；`terminal_tab_pagination_check` 用隔离的真实窗口和不联网终端验证行数、翻页、计数、搜索、自动定位、窗口缩放以及关闭后的页码。

### 标签标题的差异高亮

标签栏放不下完整标题时，光截断会让一排 `web-server-prod-01`…`-09` 变得完全无法区分。`TerminalTabTitle` 分三层处理：

- 没有可高亮的差异时，`Split` 把标题切成"前面部分 + 最后 6 个文本元素"（按 `StringInfo.ParseCombiningCharacters` 切，不是按 char，否则会切坏组合字符和 emoji）。前一列按剩余宽度省略号截断，后一列不截断，**结尾因此始终可见**。
- `FindEmphasis` 拿相邻标签的标题算公共前缀/后缀，找出**真正不同的那一段**并走高亮渲染。两条护栏：只和"足够相似"的相邻标题比较（相似度阈值 0.6）；如果综合多个相邻标题后公共部分不到标题的一半，就认为它们根本不是一个近似同名家族，不做高亮。
- 差异是纯数字时，`FindNumericDisplayRange` 会把高亮向两侧扩到数字边界并补上一点上下文，总位数不超过 4——只高亮 `1` 而周围还有数字，读起来是没有意义的。

### 一个必须知道的内存泄漏

`RefreshAutomationPeers`：Avalonia 的 automation peer 在其宿主的可视子元素变化时会把子列表标记为失效，但**在有人再次索要子元素之前，它一直返回上次构建的那份列表**——而除非挂了屏幕阅读器，否则没有人会去要。那份陈旧列表里还握着已关闭标签的 peer，而 peer 拥有它的控件，于是整个 `TerminalView`（可视树、终端缓冲区、各 ViewModel）都被吊在后面不释放。

所以关标签后要主动刷新已存在的 peer。**只刷新已经存在的，绝不创建新的**——从没有 automation 客户端问过的时候，这个操作零成本。

## 命令栏的自适应

命令栏的分区是普通的水平 `StackPanel`，**它们不会收缩**，窗口太窄时会互相盖住。所以每次布局之后比较按钮的自然宽度和可用宽度，放不下就加上 `compact` 样式类隐藏文字标签。注意用的是"可见子元素期望宽度之和 + 间距"，而不是被 Grid 夹紧过的 `DesiredSize`。

另外有一条窗口位置的健壮性检查：窗口左上角 160×48 物理像素的一条带必须与某个屏幕的工作区相交，否则标题栏就抓不住了。每次从托盘或第二次启动请求显示主窗口时都会重新检查；如果保存坐标属于已拔掉的屏幕，就先把窗口移到当前主屏幕的工作区再显示。

## 密码框与输入法

`PasswordImeGuard`（`Views/PasswordImeGuard.cs`，`App.Initialize` 里装一次）在**任何** `PasswordChar` 非空的 `TextBox` 拿到焦点时关闭 Windows 输入法，焦点离开后再把原来的开合状态还回去。装的是一个全局 class handler，所以运行期才建出来的对话框（主密码、keyboard-interactive）自动覆盖，不需要每个站点各写一遍。

几条踩过的坑：

- **只改开合状态，不禁用输入法**。用 `WM_IME_CONTROL` + `IMC_SETOPENSTATUS` 发给 `ImmGetDefaultIMEWnd` 拿到的窗口；不设 `IsInputMethodEnabled=false`，想用非 ASCII 密码的人仍然可以自己把输入法开回来。
- **class handler 会在冒泡路径上的每个元素触发**，必须只认 `e.Source`，否则密码框刚被守住就会被它的祖先立刻释放掉。
- **还回去要延后到焦点稳定之后**。Windows 是在焦点事件之后才把输入上下文挂到新控件上的，在 `GotFocus` 里同步设置的开合状态会被这次挂载吞掉，所以还原走 `Dispatcher.Post(Background)`。
- **落在不吃文字的控件上时不还**。复选框、按钮没有输入上下文，这时候发的开启请求会被丢弃；守卫会一直欠着，直到焦点落到真正能打字的控件（`TextBox` / `TerminalControl`）再还。

Debug MCP 的 `password_ime_check` 会用一个临时窗口把这三条路径（获得焦点、失去焦点、窗口带着焦点被关掉）都跑一遍；机器上没装输入法时它返回 SKIP。

## 面板尺寸与偏好

AI 面板宽度、文件浏览器高度、监控面板宽度、连接树宽度都是**跨标签页共享并持久化**的（设备无关像素）。AI 面板是否在 SSH 登录后自动打开由 AI 面板选项菜单里的"自动打开 AI 面板"决定：全局开关、机器本地存储、默认关闭。手动打开/关闭面板**不改**这个开关——原先"记住上次切换状态"的做法会让一次随手打开变成以后每个会话都开。

终端标签里的 AI 面板有四种布局：关闭、侧栏（CLI）、隐藏 SSH 终端（CLI 占满标签）、**紧凑条**。agent 跑在标签外（Windows Terminal / Desktop / IDE）时，面板正文只剩一句提示，所以面板只保留 header，作为一条横栏停靠在整个标签顶部，提示改放在状态文字的 tooltip 里，缺失的 surface 用条上带文字的安装按钮。约束：
- 同一个面板实例在侧栏 host 和顶部条 host 之间**搬移**，不新建，所以切换模式不丢状态；`AiPanelHost.IsVisible` 仍然表示"面板已打开"，紧凑时它留在宽度为 0 的列里、内容为空。
- 顶部条放在 `RootGrid` **外面**（外层 DockPanel 顶部）。放进 Grid 的 Auto 行行不通：跨越 Auto 行和 Star 行的元素（监控面板、脚本遮罩）会把期望尺寸摊进 Auto 行，把它撑高。
- 紧凑时"隐藏 SSH 终端"**不生效**，选项菜单也不显示这一项（否则整个标签只剩一条横栏）；偏好本身保留，切回 CLI 后照常生效。
- 紧凑时不写回侧栏宽度：离开侧栏前先保存当前宽度，0 宽的列不会覆盖它。
- 全局 agent 标签独占整个标签，不跟终端抢空间，所以**不用**紧凑条，外部模式下照常显示居中提示。

`ai_panel_compact_layout_check` 在禁止启动 agent 的情况下来回切换 CLI 和外部模式，验证上面这些条件。

AI 运行模式的持久化被**拆成两个槽**：有桌面 surface 的 agent 用一个，只有 CLI/Windows Terminal 的用另一个。这样为一个没有桌面版的 agent 选 CLI，不会清掉另一个有桌面版的 agent 的 Desktop 偏好。**只有一种模式的 agent 什么都不存**——它的模式本来就不是选择，写进共享槽只会抹掉一个真实偏好。

## 本地化与主题

本地化用 `Jeek.Avalonia.Localization` 的 `TabLocalizer`，词条在 `Data\Languages.tab`。语言和主题在构建主窗口之前从设置里应用。主题字符串映射：`"Light"` / `"Dark"`，其余（含空值和无法识别的值）落到 `ThemeVariant.Default`（跟随系统）。

设置窗口按“页头说明 / 可滚动内容 / 固定操作栏”分成三段。内容按外观、文件与存储、安全、更新四张卡片组织；窗口允许缩放，小尺寸下只滚动中间内容，确定和取消按钮始终可见。底部按钮遵循 Windows 从左到右“确定、取消”的顺序，并整体靠右。`settings_dialog_layout_check` 打开真实设置窗口并验证这个结构与按钮顺序，防止新增设置项重新退化成无分组的长列表。

所有普通 `Button` 的内容在水平和垂直方向都默认居中，这条规则放在 `Themes/AppControls.axaml` 的共享样式里，因此 XAML 控件和代码动态创建的对话框按钮保持一致。确实需要其它对齐方式的特殊按钮用更具体的样式或本地属性显式覆写。

## 焦点

每个终端标签记住"上次聚焦的控件"（弱引用，仅会话内，不持久化），控件不存在或不可见时回退到 SSH 终端。把焦点移进内部终端控件要**投递到 UI 线程**，让它跑在视图重新附加之后——直接聚焦 UserControl 本身不会把焦点转给终端。
